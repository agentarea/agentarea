Network — layout variants

Один и тот же моковый граф (4 агента с делегированием, 3 триггера, MCP / skills / OpenAPI). Сравни расстановку.

E · Onion layers
Концентрические слои: в ядре — оркестратор, кольцами наружу идут уровни делегирования (кто кому подчинён), а на внешнем кольце «мир» — синие точки это входящие события (ingress), розовые это внешние сервисы, куда агент ходит (egress). Чётко читается процесс «изнутри наружу».
ingress · событие → агент делегирование (слой) egress · выход во внешний сервис
D · Network zones
Сеть как VPC: ingress слева, агенты в governed-зоне, наружу — только через egress-шлюз. Инструменты делятся по scope: внутренние MCP/skills (зелёные) остаются внутри и НЕ пересекают шлюз; внешние (розовые) идут наружу. На рёбрах — permission-чипы (scope доступа + риск), агент egress-capable только если ходит к внешнему ресурсу.
ingress · событие delegates_to internal tool egress · внешний ● internal agent ↗ egress-capable ▰ critical perm
A · Layered columns
Строгие колонки Triggers → Agents → Tools, ряды выровнены по связям, без центрирующих пустот. Делегирование — мягкие дуги между агентами. Прокачанная версия текущего вида.
trigger → agent delegates_to uses tool / skill
B · Constellation
Оркестратор в центре, под-агенты по кольцу, инструменты каждого агента — спутники рядом с ним. Триггеры цепляются снаружи к своему агенту. Хорошо читается «кто чем владеет».
trigger → agent delegates_to uses tool / skill
C · Grouped cards
Каждый агент — карточка, его skills / MCP / OpenAPI лежат чипами внутри. Внешняя колонка и сотни рёбер исчезают. Триггеры — пилюли слева, делегирование — стрелки между карточками.
trigger delegates_to ■ tool/skill chip
